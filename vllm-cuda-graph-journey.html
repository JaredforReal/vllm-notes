Architecture Overview
全局概览
CUDA Graph 解决的是 decode 阶段 CPU kernel launch overhead：一轮 decode 的 GPU 计算由很多小 kernel 组成，逐个 launch 让 CPU 成为瓶颈。CUDA Graph 把一串 GPU 操作录制成图，之后 graph.replay() 一次提交整段计算。

两个硬约束：① replay 时输入/输出/中间 buffer 的地址必须和 capture 时一致；② replay 时 shape、kernel grid、控制流必须和 capture 时一致。

三个核心概念

CUDAGraphMode

用户配置 + 运行时模式。配置态可以是组合模式 (FULL_DECODE_ONLY, FULL_AND_PIECEWISE)；运行时只会是 NONE PIECEWISE FULL 之一。

BatchDescriptor

运行时 CUDA Graph dispatch key。描述 padded 后的 num_tokens、num_reqs、uniform 和 LoRA 状态。

ForwardContext

把 dispatch 结果带进模型内部。CUDAGraphWrapper 只相信它，不重新做调度判断。包含 cudagraph_runtime_mode、batch_descriptor、attn_metadata、slot_mapping 等。

FULL vs PIECEWISE 一眼区分
维度 FULL PIECEWISE
录制范围整个模型 forward编译切分后的若干子图
Attention通常包含在 graph 内通常作为 unsafe op 留在 graph 外
request padding需要固定 num_reqsnum_reqs=None，只关心 num_tokens
典型场景uniform decode，尤其纯 decodemixed prefill-decode / 后端不支持 full attention graph
调度优先级优先尝试FULL 不匹配时再尝试
源码主路径外层 CUDAGraphWrapper(runtime_mode=FULL)子图 CUDAGraphWrapper(runtime_mode=PIECEWISE)

Capture Sizes 初始化
VllmConfig._set_cudagraph_sizes() (vllm.py) │ ├─ enforce_eager 或 mode=NONE: │ └─ max_cudagraph_capture_size = 0, capture_sizes = [] │ ├─ 确定 max_cudagraph_capture_size │ ├─ 用户显式设置 → 使用用户值 │ └─ 默认: min(max_num_seqs * decode_query_len * 2, 512) │ ├─ 生成 capture sizes │ ├─ interactivity: 1..min(max_size, 32) │ └─ 默认: [1,2,4] + range(8,256,8) + range(256,max+1,16) │ ├─ max_num_batched_tokens 在范围内 → 也加入 ├─ sequence parallelism → 调整到 TP 兼容大小 └─ post_init_cudagraph_sizes()
capture size 是 token 数，不是 request 数。对纯 decode 而言 num_tokens ≈ num_reqs * decode_query_len。speculative decoding 下 decode_query_len = 1 + num_speculative_tokens，capture size 需要被调整为它的倍数。

EncoderCudaGraphManager.capture() │ └─ for token_budget in budgets: └─ _capture_budget_graph(budget) ├─ prepare_encoder_cudagraph_capture_inputs(...) ├─ output = encoder_cudagraph_forward(...) ├─ output_buffer = empty_like(output) ├─ graph = torch.cuda.CUDAGraph() ├─ with torch.cuda.graph(graph): │ ├─ output = encoder_cudagraph_forward(...) │ └─ output_buffer.copy_(output) └─ budget_graphs[budget] = Metadata
Replay 调用栈
encoder_cudagraph_manager.execute(mm_kwargs) │ ├─ _execute_local(mm_kwargs) │ ├─ 计算每个 item 的 output token 数 │ ├─ 按 token 数升序 greedy pack │ ├─ 找 smallest fitting token_budget │ ├─ prepare_encoder_cudagraph_replay_buffers(...) │ ├─ _run_budget_graph(...) │ │ ├─ copy actual → captured input_buffer │ │ ├─ zero + copy metadata buffers │ │ ├─ graph.replay() │ │ └─ return output_buffer │ └─ scatter slices → 恢复原始顺序 │ └─ mm_encoder_tp_mode == "data": ├─ _dp_shard(...) ├─ 每个 TP rank 本地 execute └─ _dp_gather(...)

Appendix
横切关注点
内存池与 Capture 顺序
get_global_graph_pool() — 共享的 graph pool
Capture 顺序：大尺寸优先、PIECEWISE 先于 FULL
lock_workspace() capture 后锁住 workspace
避免 runtime resize 破坏 graph 假设
持久化输入 Buffer
CUDA Graph replay 要求地址不变，运行时写入已有 buffer：
input_ids, positions, seq_lens
query_start_loc, slot_mapping, block tables
非 PP rank 0 的 intermediate_tensors
Attention Padding
FULL：attention 也在 graph 内
→ metadata 也必须按 padded 形状构建
→ padding seq_lens 为 0, slot_mapping 填 -1

PIECEWISE：attention 在 graph 外
→ 通常只需要 token padding 给子图
LoRA Graph Specialization
cudagraph_specialize_lora=True
→ 为 0 / 有 LoRA / 各 active count 捕获不同 graph

cudagraph_specialize_lora=False
→ 用 "max_loras + 1" 的通用 LoRA graph 覆盖
Speculative Decoding
uniform_decode_query_len = 1 + num_speculative_tokens
FULL decode graph 的 num_tokens 必须是它的倍数
Attention backend 至少要支持 UNIFORM_BATCH
否则 FULL decode 会降级
Offloader 与 Copy Stream
Capture 前：sync_prev_onload()
Capture forward 后：join_after_forward()
Replay 前：再次 sync
→ 避免 async copy 和 graph replay 交叉写同一 buffer
观测指标
observability_config.cudagraph_metrics=True → 生成 CUDAGraphStat：
num_unpadded_tokens | num_padded_tokens | num_paddings | runtime_mode
进入 v1 metrics/logger，便于观察 padding 浪费和 graph 命中模式。
