KV cache 的种类：Full Attention / MLA / SparseMLA / Linear 状态缓存

前面讲的 allocate_slots / prefix cache / 抢占都是机制，跟"缓存存什么"无关。KVCacheSpec（每层一份）描述"存什么、block 多大"，SingleTypeKVCacheManager 描述"怎么分配/命中/释放"。spec 决定内容与尺寸，manager 决定调度行为，注册表绑定（single_type_kv_cache_manager.py:1380-1415）。

基本情况：Full Attention（per-token K/V）
每层一个 KV 张量，shape（flash-attn 后端 flash_attn.py:149）： (num_blocks, 2, block_size, num_kv_heads, head_size) ↑ ↑ ↑ ↑ ↑ 物理block数 K和V slot数=token数 KV头数 每头维度 • block_size = slot 数 = 每 block token 数（默认 16，须 16 倍数） • 2 = K 和 V 拼出的维度；一 block(一层) 内存 = block_size × num_kv_heads × (head_size+head_size_v) × dtype (FullAttentionSpec.real_page_size_bytes, kv_cache_interface.py:323-328) • block_table 跨层共享：token 位置 p、第 L 层 K/V = kv_cache[L][ block_table[p//block_size] ][p%block_size] • 内存 O(seq_len)：max_memory_usage_bytes = cdiv(max_model_len, block_size) × page_size_bytes (:236-244)
一个 token 一次 forward 为每层都产生一对 K/V——不矛盾：层是张量独立维度，slot 只承担"位置"。block_table 是 block 维的 1D 投影，跨层复用。
MLA：latent 压缩缓存（DeepSeek-V2/V3）
每层每 token 缓存 = kv_c_normed (kv_lora_rank=512) + k_pe (qk_rope_head_dim=64) = 576 元素/token (DSv3) ★ V 根本不缓存 —— attention 时用 kv_b_proj 上投影从 latent 重建 V cache shape = (num_blocks, block_size, head_size=576), num_kv_heads=1 (mla_attention.py:1216-1223) real_page_size_bytes = storage_block_size × 1 × head_size × dtype —— 没有 2 (kv_cache_interface.py:393-398) 写入：concat_and_cache_mla(kv_c_normed, k_pe, kv_cache, slot_mapping) (v1/attention/backend.py:963-983) 省多少：DSv3 标准注意力本要 128 头×(128+64)K + 128×128 V；MLA 只存 576 维 latent ≈ 128× 缩减 absorption（mla_attention.py:696-832）： decode → forward_mqa 吸收路径：q_nope @ W_UK_T 进 latent 空间做 attention，输出 W_UV 投回 V (:778-832) ★ decode 不展开 latent 成完整 K/V，省显存省带宽 prefill → forward_mha 展开路径：kv_b_proj(kv_c_normed) 展开成完整 K/V 跑标准 MHA (:2317-2321) 吸收权重在 process_weights_after_loading 预备 (:899-962)
SparseMLA：两种"稀疏"，别混淆
① SlidingWindowMLASpec（kv_cache_interface.py:550）："Sliding window attention with MLA cache format"——滑窗注意力 + MLA latent 缓存，窗口外 block 回收。→ SlidingWindowManager。
② Top-k 选择稀疏 MLA（DeepSeek V3.2/V4 的 index_topk）——社区常说的 sparse MLA： 独立 indexer 注意力算 query 对所有已缓存 token 的相关度，选 top-index_topk（通常 2048）个位置 (deepseek_v2.py:603-674 Indexer; top-k kernel sparse_attn_indexer.py + csrc/libtorch_stable/topk.cu) 主 MLA attention 只对这 top-k token 做注意力，而非全序列 ★ 缓存内容不变 —— 还是同一个 MLA latent 张量；只是 kernel 用 top-k block table gather 2048 个 latent (v1/attention/backends/mla/*_sparse.py, is_sparse()=True, 只有 forward_mqa) FP8 打包：DSv3.2 656 字节/token, DSv4 584 字节/token (flashmla_sparse.py:65-87,132-144) 启用：config 带 index_topk 即 V3.2 (deepseek_v2.py:1243-1253 自动探测); V4 用 model_version="deepseek_v4"
